## 发现详情

### AUD-2026-002-F01：未消费的请求体可能破坏持久 HTTP/1.1 连接边界

- **严重程度：** P2
- **当前状态：** 开放
- **受影响组件：** `state-service/main.py:1611-1642`、`1883-2073`
- **证据与复现：** 处理器启用 HTTP/1.1。只有 `_read_dashboard_json()` 和上传路径会在读取前控制 `close_connection` 并消费受限正文；普通 GET、405、404、控制接口和其它提前返回路径不会统一拒绝、消费或关闭携带正文的请求。静态代码因此允许未读字节留在持久连接中，并被基础处理器作为后续请求输入解释。按本轮限制未进行网络复现。
- **影响：** 如果反向代理向后端转发此类正文并复用连接，可能造成请求/响应队列错位或跨请求边界的意外处理。若代理始终缓冲、剥离异常正文或不复用连接，实际影响会下降。
- **现有缓解：** 正常 JSON 写入和上传路径有正文长度、读取和关闭连接控制；服务只监听回环地址，预期由 Zoraxy 代理。
- **修复建议：** 在路由分派前建立统一的请求体策略；拒绝不支持的 `Transfer-Encoding` 和重复/歧义 `Content-Length`；所有不接受正文或提前返回的路径应安全消费已知小正文或强制 `Connection: close`。增加不依赖真实网络的处理器单元测试。
- **Issue / 修复 Commit：** 待定
- **修复版本：** `Unreleased`
- **复测结果：** 待定

### AUD-2026-002-F02：HTTP 处理线程和读取时间缺少服务端上限

- **严重程度：** P2
- **当前状态：** 开放
- **受影响组件：** `state-service/main.py:1582-1613`、`1644-1734`
- **证据与复现：** `ThreadingHTTPServer` 为连接创建守护线程，但代码未设置接受套接字的读取超时、请求总截止时间、并发连接上限或有界处理池。`rfile.read(content_length)` 可一直等待不足的正文。字节上限只能限制完整请求大小，不能限制等待时间或同时等待的线程数。
- **影响：** 在上游允许慢速/不完整转发或本地进程直连的条件下，连接可长期占用线程、内存和句柄，最终降低或耗尽服务可用性。
- **现有缓解：** 回环监听、上游反向代理，以及各业务端点的正文大小限制。
- **修复建议：** 为连接设置短而明确的读超时和单请求截止时间；用信号量或有界工作池限制并发处理；超时响应后关闭连接；在部署文档中明确 Zoraxy 的请求头、正文、空闲和上游超时要求。
- **Issue / 修复 Commit：** 待定
- **修复版本：** `Unreleased`
- **复测结果：** 待定

### AUD-2026-002-F03：大图片和无上限清单在全局状态锁内执行重工作

- **严重程度：** P2
- **当前状态：** 开放
- **受影响组件：** `state-service/main.py:501-685`、`786-860`
- **证据与复现：** 单文件允许 50 MiB、1 亿像素。图片完整解码、EXIF 转换、RGB 转换、裁切、WebP 编码及缩略图校验都可能在 `StateStore._lock` 持有期间执行。`list_backgrounds()` 还会在同一把锁内枚举全部文件并串行生成所有缺失缩略图，且没有总文件数、总像素、总时间或分页上限。
- **影响：** 一张成本很高的合法图片或大量合法文件可造成显著 CPU/内存压力，并阻塞偏好读取、更新、上传和删除等其它状态操作。

### AUD-2026-002-F06：构建控制台冒烟进程可在进入清理前永久阻塞

- **严重程度：** P2
- **当前状态：** 开放
- **受影响组件：** `scripts/build-state-service.ps1:151-195`
- **证据与复现：** 构建脚本依次同步调用标准输出 `ReadToEnd()`、标准错误 `ReadToEnd()` 和无超时 `WaitForExit()`。如果产物不退出、保持输出打开，或在父进程尚未读取的管道写满，控制流无法进入 `finally`；`Kill()` 和临时目录清理因此也无法执行。
- **影响：** 回归或受污染的构建产物可永久挂起本地发布/CI 作业，并留下临时构建状态，直至外部操作者或平台超时终止。

- **修复建议：** 并发异步读取 stdout/stderr；为进程退出设置硬截止时间；超时后终止整个进程树并等待确认；确保清理逻辑不依赖同步读结束。

## 已确认的主要防护

- Bestdori 使用固定 HTTPS 主机、拒绝重定向、限制内容类型和大小，并对下载图片复用本地图片验证；
- PowerShell 脚本未使用 `Invoke-Expression` 或 `cmd /c` 拼接执行，卸载操作目标固定且受 `ShouldProcess` 保护；
