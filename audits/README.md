# 审计报告管理与格式指引

本目录保存已经完成或正在跟踪的周期性代码、架构和安全审计报告。它不是普通代码审查评论、漏洞利用材料或日常 TODO 的存放位置。

## 报告索引

| 报告编号 | 初次审计日期 | 审计范围 | 代码基线 | 发现 | 最终状态 | 报告 |
|---|---|---|---|---:|---|---|
| `AUD-2026-001` | 2026-07-23 | CORS 重构、服务探测、启动边界、卸载与文档 | `d202e18` | 4 | 全部关闭于 `V1.0.2` | [查看报告](2026-07-23-business-implementation-audit.md) |
| `AUD-2026-002` | 2026-07-26 | 当前 HEAD 的运行时代码、测试与维护脚本静态审计 | `0dad68d` | 8 | 全部关闭于 `V2.5.2` | [查看报告](2026-07-26-repository-wide-audit.md) |

表中的 Commit SHA 对应 GitHub 公共镜像；该镜像因公开前的历史净化与私人 Gitea 使用不同 SHA，审计范围、发现和修复版本不变。

## 管理原则

1. **一轮审计一份报告。** 新审计创建新文件，不向旧报告连续追加无关发现。
2. **报告绑定代码基线。** 必须记录被审计的 Commit SHA 或版本标签；没有基线的结论不能代表确定的代码状态。
3. **原始发现不可被修复结果覆盖。** 修复后更新状态、修复 Commit、发布版本和复测结果，但保留原始证据、影响和建议。
4. **归档报告保持稳定。** 报告关闭后只允许追加带日期的勘误；不得静默改写历史结论。
5. **修复版本以 CHANGELOG 为准。** 不根据 Commit 日期猜测发布版本；尚未发布时填写 `Unreleased`。
6. **普通代码审查留在 PR。** 行级评论、讨论和批准状态由 Gitea/GitHub PR 保存；只有跨组件或周期性的正式审计进入本目录。
7. **安全发现先私下修复。** 未修复且可被利用的细节不应进入公开报告；修复发布后再决定是否生成脱敏披露。
8. **不夸大验证性质。** 明确区分维护者回归验证、独立复测和第三方审计；未执行的检查必须写入限制。

## 文件与编号规则

- 文件名：`YYYY-MM-DD-<scope>-audit.md`
- 报告编号：`AUD-YYYY-NNN`
- 发现编号：`AUD-YYYY-NNN-FNN`
- `<scope>` 使用简短的小写英文和连字符，例如：
  - `2026-08-02-thumbnail-security-audit.md`
  - `2026-09-15-release-readiness-audit.md`

报告日期使用初次审计日期。后续修复和复测日期写入报告元数据，不通过重命名文件表达。

## 严重程度

| 等级 | 定义 |
|---|---|
| P0 | 已造成或极可能立即造成严重安全、数据或生产事故，必须停止发布并立即处理 |
| P1 | 高影响问题，存在明确利用条件、数据风险或关键业务中断风险，应优先修复 |
| P2 | 中等影响问题，在特定条件下影响安全、可靠性或维护性，应纳入近期修复 |
| P3 | 低影响问题，主要影响边界场景、文档准确性、可维护性或防御纵深 |

严重程度描述风险，不等于修复优先级的唯一依据。报告应同时说明触发条件、影响范围和现有缓解措施。

## 状态

| 状态 | 含义 |
|---|---|
| 开放 | 发现有效，尚未开始修复 |
| 修复中 | 已有明确修复工作正在进行 |
| 待复测 | 修复已完成，但尚未验证原问题和回归风险 |
| 已关闭 | 修复和复测均已完成 |
| 接受风险 | 明确认可剩余风险并记录原因、责任人和复查日期 |
| 不适用 | 复核后确认不影响本项目或原发现前提不成立 |

## 建议工作流

1. 在开始审计前记录工作树状态、Commit SHA、版本和范围；
2. 执行静态审查、自动化检查及范围内需要的动态测试；
3. 为每项有效发现分配唯一编号和严重程度；
4. 需要跨 Commit 跟踪时创建项目 Issue，并在报告中关联；
5. 使用独立修复 Commit 处理发现，CHANGELOG 记录用户可感知的修复；
6. 在原始基线可复现的前提下验证问题，再对修复版本执行回归测试；
7. 填写修复 Commit、发布版本、复测结果和剩余风险；
8. 全部发现关闭或明确接受风险后，将报告标记为归档；
9. 在本 README 的索引中增加报告，不修改旧报告来代表新版本。

## 报告模板

复制下面的模板创建新报告，并删除不适用的占位说明：

````markdown
# AUD-YYYY-NNN：审计标题

> 本报告仅覆盖指定代码基线和审计范围，不代表仓库的持续安全状态。

## 报告元数据

| 字段 | 内容 |
|---|---|
| 报告编号 | `AUD-YYYY-NNN` |
| 初次审计日期 | YYYY-MM-DD |
| 修复复核日期 | 待定 |
| 审计代码基线 | `<commit-sha>` 或 `<version-tag>` |
| 审计范围 | 组件、接口和变更范围 |
| 使用的方法与工具 | 静态审查、测试命令、扫描器及版本 |
| 最终状态 | 开放 / 修复中 / 待复测 / 已关闭 / 接受风险 |
| 独立第三方复测 | 未安排 / 已完成并说明执行方 |

## 总体结论

用一至三段说明总体风险、发现数量、最高严重程度和是否建议发布。

## 覆盖范围与限制

### 已覆盖

- 被检查的组件、接口和数据流；
- 实际执行的命令与测试。

### 未覆盖

- 未执行的构建、平台、渗透测试或外部依赖检查；
- 不能由本报告结论覆盖的部分。

## 发现汇总

| 发现编号 | 严重程度 | 标题 | 当前状态 | Issue / 修复 Commit | 修复版本 |
|---|---|---|---|---|---|
| `AUD-YYYY-NNN-F01` | P2 | 示例发现 | 开放 | `#123` | `Unreleased` |

## 发现详情

### AUD-YYYY-NNN-F01：示例发现

- **严重程度：** P2
- **当前状态：** 开放
- **受影响组件：** `path/to/file`
- **证据与复现：** 说明代码位置、触发条件和可重复证据
- **影响：** 说明安全、数据、可用性或维护影响
- **现有缓解：** 没有时填写“无”
- **修复建议：** 给出可验证的修复方向
- **Issue / 修复 Commit：** 待定
- **修复版本：** `Unreleased`
- **复测结果：** 待定

## 修复后复测

- 原问题复现结果；
- 新增或更新的自动化测试；
- 完整回归、构建和目标平台冒烟结果；
- 独立复测执行方及结论；未安排时明确写出。

## 剩余风险与后续处理

- 尚未关闭、接受风险或超出范围的事项；
- 后续复查日期和触发条件。

## 勘误

- 无。
````

## 公开与脱敏

- 报告不得包含真实访问令牌、密码、私钥、Cookie、个人信息或可直接利用的生产配置；
- HomeLab 域名、内网拓扑、管理入口和精确路径在公开前应按展示需要脱敏；
- 未修复漏洞应在私有 Issue、私有分支或安全通报渠道中处理；
- 对外发布时保留风险类别、影响版本、修复版本和缓解措施，避免公开不必要的利用细节。
