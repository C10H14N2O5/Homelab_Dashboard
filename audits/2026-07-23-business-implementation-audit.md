## 发现详情

### AUD-2026-001-F01：实际 EXE 目录未被正确检查

- **严重程度：** P2
- **最终状态：** 已关闭
- **受影响组件：** `state-service/main.py`
- **基线位置：** `run_configuration_wizard()`，审计基线约第 1133 行
- **现象与证据：** `app_dir` 来自 `config_path.parent`，检查的是配置文件目录，而不是实际 EXE 所在目录。
- **影响：** 使用 `--config` 指向 Web 根之外的配置时，即使 EXE 位于公开 Web 根目录，也可能绕过“EXE 必须位于公开 Web 根之外”的约束。
- **修复建议：** 使用 `application_directory()` 获取实际程序目录，并在配置向导以及普通 `serve`、`monitor` 等启动路径加载配置后统一执行检查。
- **实际修复：** 新增统一的实际程序目录校验；配置向导和所有普通启动模式均拒绝程序目录位于公开 Web 根内。
- **修复 Commit：** `de04ba3`
- **发布版本：** `V1.0.2`
- **复测结果：** 通过程序目录边界相关单元测试及打包 EXE 冒烟测试。

### AUD-2026-001-F02：健康检查没有验证服务版本

- **严重程度：** P2
- **最终状态：** 已关闭
- **受影响组件：** `state-service/main.py`
- **基线位置：** `health()` 与后端复用判断，审计基线约第 914–918 行
- **现象与证据：** `/healthz` 已返回 `version`，但启动器只验证 `status` 和 `service`。
- **影响：** 同名但接口契约版本不同的进程占用 8787 端口时，可能被 `ensure_backend()` 误认为可复用后端，导致新版后端不启动，随后出现接口缺失或响应契约不匹配。
- **修复建议：** 同时要求 `payload.get("version") == SERVICE_VERSION`，并增加版本不匹配时拒绝复用的回归测试。
- **实际修复：** 启动器只接受 `status`、`service` 和 `version` 均完全匹配的后端；其它或不兼容监听器不会被复用。
- **修复 Commit：** `de04ba3`
- **发布版本：** `V1.0.2`
- **复测结果：** 精确服务版本、接口契约和拒绝不兼容监听器的回归测试通过。

### AUD-2026-001-F03：EXE 不存在时卸载脚本会提前中断

- **严重程度：** P3
- **最终状态：** 已关闭
- **受影响组件：** `scripts/uninstall-state-service.ps1`
- **基线位置：** 原审计位置约第 13–14 行
- **现象与证据：** 脚本在 `Test-Path` 之前调用 `Resolve-Path`；由于启用了 `$ErrorActionPreference = 'Stop'`，路径不存在会直接终止脚本。
- **影响：** 如果 EXE 已被手动删除，后续 Startup 快捷方式及遗留计划任务将无法继续清理。
- **修复建议：** 先调用 `Test-Path`，确认文件存在后再执行 `Resolve-Path`；EXE 缺失时仍继续完成其余卸载步骤。
- **实际修复：** 卸载脚本先检查原始路径，EXE 缺失时继续清理 Startup 快捷方式和遗留计划任务。
- **修复 Commit：** `de04ba3`
- **发布版本：** `V1.0.2`
- **复测结果：** PowerShell 语法和缺失 EXE 时的卸载行为检查通过。
